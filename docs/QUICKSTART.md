# はじめて使う人のセットアップ

対象：Windowsで、既存のUnityプロジェクトとClaude DesktopのCodeを使う場合の任意の制作テンプレート。更新日：2026-10-15。KOUによる最初のローカルCLIを試す場合は[README](../README.md#はじめる)へ進んでください。外部AIやUnityは不要です。

**実装済みCLIは設定・ファイル検査とJSON記録に限定されます。生成スクリプト、Unityプラグイン、制作工程の自動テストはまだ入っていません。** `doctor` や `generate` は将来の機能名です。その名前のコマンドを実行しないでください。以下の制作テンプレートを使う場合は、手元の環境を調べ、実装計画を確認するところから始めます。

所要時間は、既存環境、初回インポート、必要な実装で変わります。「10分で完成」「夜間に必ず完走」とは保証しません。本資料のレビューは文書の確認であり、あなたのPCでのUnity／Blender動作確認を済ませたという意味ではありません。

## 1. 最小構成を選ぶ

最初は次の組み合わせだけを使います。

- Claude Desktopの **Code → Local**：プロジェクトを調査し、承認後に必要なスクリプトを実装する。
- 既存Unityプロジェクトと、そのプロジェクトが指定するUnity Editor：取り込み・再生・ビルドを確かめる。
- Blender：承認後に、自作道路1個を生成・書き出しする。繰り返し処理はBlender Python／CLIを基本にする。
- Gitと復旧用バックアップ：既存変更を守り、何を変えたかを追う。

**MCP、Superpowers、Blender Game Skillsは初回の必須条件ではありません。** MCPなしで、ファイル、スクリプト、ログ、保存画像、人によるEditor操作を組み合わせるところから始めます。画面操作ができない場合は、必要な操作だけオーナーが行い、その事実を記録します。Codeがローカルファイルを扱えることと、Unityの画面を自動操作できることは別です。

既存のClaude MaxでCodeが利用できる状態なら、追加SaaSやAPI契約は初回不要です。利用枠は無制限ではありません。追加支出上限は0円を初期値にし、上限到達時は止めます。Unity利用資格や素材のライセンスは各自の条件で確認してください。

## 2. 人とAIの担当を分ける

| 担当 | 行うこと |
|---|---|
| オーナー（あなた） | 対象フォルダの指定、既存作業の保存、必要な承認、実画像・音・試遊の最終確認 |
| 実装担当（Claude Code） | 環境調査、計画、承認範囲の実装、実行ログと証拠の保存 |
| レビュー担当（人またはAI） | 指定された証拠を確認し、合否と未確認事項を記録。元Scene／.blendは変更しない |

最初は実装担当を1セッションだけにします。別のAIが同じSceneや.blendを編集しているなら、先に止めるか、既存セッションへ作業を統合してください。

## 3. フォルダとアプリを用意する

### 3.1 既存プロジェクトを確認する

Windowsのエクスプローラーで、対象Unityプロジェクトを探します。`Assets`、`Packages`、`ProjectSettings` が並ぶフォルダがプロジェクトのルートです。`Assets`だけを選ばないでください。

1. Unity／Blenderで編集中なら保存する。既存の作業担当がいれば引き継ぐ。
2. `ProjectSettings/ProjectVersion.txt` に記載されたEditor版を確認する。最新版への更新やプロジェクト変換はしない。
3. Unity Hubでその版があるか、Blenderがインストールされているか確認する。わからなければ「不明」のまま次の調査へ渡す。
4. Gitが使えるか、バックアップ先を用意できるか確認する。未コミットの変更や未追跡ファイルも保護対象にする。

ソフトが見つからない場合、似た名前のコマンドやインストール手順を推測して実行しないでください。準備プロンプトで不足を報告させ、必要なソフト・公式取得元・対応版・権限を確認してから導入を判断します。既存Unityプロジェクトがない場合もここで止め、新規プロジェクトの作成計画を別途決めてください。

### 3.2 3つのルートを区別する

以下は説明用の架空パスです。実在する自分のフォルダへ置き換えます。環境変数や、キットが自動で読む設定項目ではありません。

| 名前 | 意味 | 例 |
|---|---|---|
| `HARNESS_REPO` | この公開キットを展開した場所。README、docs、promptsがある | `C:\GameWork\game-production-harness` |
| `PROJECT_ROOT` | 変更する既存Unityプロジェクトのルート | `C:\GameWork\MyUnityGame` |
| `WORK_ROOT` | 非公開の実行記録・検証用出力を置く場所 | `C:\GameWork\harness-local` |

エクスプローラーで3つの場所を確認し、それぞれのアドレス欄から実パスを控えます。`WORK_ROOT`は新しく空のフォルダを作り、原則として`HARNESS_REPO`と`PROJECT_ROOT`の外に置きます。これ自体を公開リポジトリにしないでください。既存の私用ファイルが入ったフォルダを流用しません。非公開ゲームの配下へ置く場合も、Gitの追跡対象外であることを確認してから書き込みます。

公開キットの`CLAUDE.md`を既存ゲームの同名ファイルへ上書きしないでください。ゲームのソース、参考画像、購入素材、ローカル設定も公開キットへコピーしません。

## 4. Claude Desktopで正しい入口を開く

1. WindowsのClaude Desktopを起動し、既存の契約アカウントでサインインする。
2. **Code** タブを選ぶ。通常のChatやCoworkへ貼る手順とは別です。
3. 実行環境で **Local** を選ぶ。最初の確認でCloudやWSLへ切り替えない。
4. **Select folder** で上の`PROJECT_ROOT`を選ぶ。
5. 権限モードは **Manual**（旧表記ではAsk permissionsなど）を選び、ファイル変更とコマンドを確認する。Bypass permissionsを有効にしない。
6. [準備プロンプト](../prompts/PREFLIGHT.md)の「A. 調査と計画」を開く。入力欄を実パスへ置き換えて送る。

資料を読むために`HARNESS_REPO`へのアクセスが必要です。フォルダ外の読み取りができなければ、README、QUICKSTART、WORKFLOW、HARNESS_SPEC、SOURCESをファイルとして添付するか、その本文を渡します。AIに読み取れたファイル名を答えさせ、読めていない資料を読了扱いさせません。公開URLだけを渡しても、内容を取得できなければ読了にはなりません。

`WORK_ROOT`への書き込み許可が求められたら、そのフォルダに限定して判断します。ドライブ全体への許可は不要です。許可できない場合は、計画を会話で受け取り、まだレポートファイルを保存できていないことを記録します。Planモードで相談することもできますが、ファイル保存・実装は承認後に適切なモードへ切り替えて行います。

Codeタブの利用に、別途Node.jsやClaude Code CLIを入れる必要はありません。CLIを選ぶ場合は別の導入手順です。画面の名称や対応条件が変わった場合は、[ClaudeのDesktop開始手順](https://code.claude.com/docs/en/desktop-quickstart)と[Desktopリファレンス](https://code.claude.com/docs/en/desktop)を確認してください（2026-10-15確認）。

## 5. 調査結果を見てから、最小実装を承認する

最初の返答で、次の項目が揃っているか確認します。

- 正しい`PROJECT_ROOT`とEditor版を特定できたか。
- Blender／Unity／Gitの実在する場所・版、使えない機能を示しているか。
- 既存差分、未追跡データ、バックアップと復旧の方法が明確か。
- 最初に実装するファイルと、変更するUnity Scene／Prefabの範囲が少数に絞られているか。
- 不足ソフト、追加権限、録画、Androidモジュールなどの承認待ちが明記されているか。
- 実行前の項目を「成功」にしていないか。

計画に納得したら、[準備プロンプト](../prompts/PREFLIGHT.md)の「B. 合意した最小実装と接続確認」を、対象ファイルと許可する範囲を記入して送ります。これにより、**これから必要なスクリプトを作り、そのスクリプトを検証する**作業を開始します。未提供のハーネスを起動する操作ではありません。

最初の到達点は、自作道路1個のBlender生成 → 書き出し → Unity取り込み → Play表示 → 証拠付きレポートです。その後、音入り録画、Androidビルド、停止・再開を確認します。MCPを入れないと進められない箇所が本当にあるかは、この時点で判断します。

## 6. 結果はどこを見るか

以下は**各自の`WORK_ROOT`を基準**とした保存先です。キット同梱のフォルダではなく、実作業時に作成します。`<run-id>`は例として`20261015T090000Z-preflight`のような日時と用途を含む重複しない名前にします。

```text
WORK_ROOT/
  runs/<run-id>/
    PREFLIGHT_REPORT.md   環境、計画、実行結果、止まっている理由
    HANDOFF.md            最後の検証済み地点と次の操作
    MORNING_REPORT.md     夜間作業をした場合だけ作る結果報告
    logs/                実行コマンド、終了コード、ログ
    images/              固定条件の画像と画像レビュー
    video/               音入り実プレイ録画
    builds/              実際に作れたビルドのみ
```

画像・動画を取得できなかったときは、空の代用品で成功を装わず、報告に不足理由を記載します。レポートの証拠リンクはその`runs/<run-id>/`からの相対パスにします。絶対パス、ゲーム素材、ログ、録画には私的情報が含まれ得るので、このフォルダを丸ごと公開しないでください。

### 最初の合格判定

- Blenderから実データを書き出せた。寸法、UV、材質、欠落テクスチャを確認した。
- AIまたは人が実際の画像を開き、対象ファイルと観察内容を記録した。
- UnityのコンパイルとPlay表示をそれぞれ確認した。ピンク色や欠落材質、重大な貫通がない。
- 音声収録と実際の試聴評価を別々に記録した。聞いていない場合は試聴評価を`not_run`にした。
- Androidビルドと端末実行を別々に記録した。端末未接続なら実機検証は`not_run`。
- 保存後に止め、検証済み地点から再開できるか確認した。

いずれか不足なら「全部完了」にはしません。基本のBlender→Unity往復、復旧、保存・停止・再開が未確認なら夜間作業へ進みません。音／Androidが未確認の場合は、その範囲を除外する限定作業の明示承認を得ます。夜間作業は、確認済みの範囲・停止時刻・予算を明記した[夜間プロンプト](../prompts/OVERNIGHT.md)で別途開始します。端末未接続でも実機以外の承認済み作業は可能ですが、実機性能を合格とは報告できません。

夜間プロンプトの実パスや確認済み操作は、準備を行ったClaudeに記入済みの案を作らせます。オーナーは停止時刻・予算・制約を中心に確認し、同じ情報を一から入力し直す必要はありません。

各工程のタイムアウトと保存用の余裕時間を計画で決めます。同じ合格条件に対する修正試行は最大2回で、セッション再開や担当変更でも回数をリセットしません。クラッシュや時間切れを成功扱いせず、保存と原因記録を優先します。

## 7. よくあるつまずき

| 症状 | 次にすること |
|---|---|
| Codeタブがない／認証エラー | アカウント、Desktop版、組織の利用設定を公式手順で確認。勝手にAPI課金へ切り替えない |
| プロジェクトを読めない | Localと選択フォルダを確認。`Assets`ではなくUnityルートを指定。拒否された権限を回避しない |
| 実行ファイルが見つからない | Hubやインストール先で実パスを確認。シェルのPATHだけで未導入と決めつけない。存在しなければ停止し導入案を確認 |
| Unityの版が合わない | `ProjectVersion.txt`を基準にする。新しいEditorで開いて変換しない |
| 同じプロジェクトが使用中 | 他の担当と調整して保存する。同じプロジェクトでEditorとバッチ処理を競合させたり、強制終了したりしない |
| GLBをUnityへ取り込めない | 実プロジェクトのインポーターを確認。FBX等の対応済み形式を検討。追加パッケージは承認後に導入 |
| 画像はあるがAIが見られない | 人が開いてレビューするか、工程を`blocked`／`not_run`にする。数値検査で画像評価を代用しない |
| 動画に音がない／聞けない | 録画方式、音声トラック、無音を確認。人が試聴した結果も記録。推測で音を合格にしない |
| Androidモジュール／端末がない | ビルド不可と実機未実施を分ける。必要な導入・接続はオーナーに確認し、限定作業の範囲を決める |
| レポートが見つからない | `WORK_ROOT`、run-id、実際の保存成功を確認。会話内の予定パスは保存済みの証拠ではない |
| 利用枠、権限待ち、繰り返す失敗で停止 | 原因と再開地点を保存。追加課金、Bypass、別アカウントでの回避をしない |

## 8. MCPを追加したくなったら

まず[接続候補と出典](SOURCES.md)を読みます。Blender公式MCP、コミュニティ製Blender MCP、CoplayのBridgeは別実装で、名前が似ていても互換とは限りません。

追加前に、取得元URL、固定するバージョン、対応するBlender／Unity／サーバー／アドオンの組み合わせ、ライセンス、起動方式、ポート、ファイルとコード実行の権限、無効化方法を記録します。MCP経由のPython実行もコード実行です。ローカル接続を基本にし、インターネットへポートを公開しません。

不足を特定したうえでオーナーが導入を承認し、代表アセット1個で検証します。MCP導入だけで見た目・音・性能の合格が保証されることはありません。
