# NOTEとGitHubの公開手順

## 公開段階を分ける

初回は「調査と設計メモ」として公開できる。実装、動作保証、Androidでの成功実績は未達として明記する。実装後は、再現可能な最小例と失敗例を追加して更新する。

## GitHub

公開先：[deguchi35/game-production-harness](https://github.com/deguchi35/game-production-harness)。既存のゲームリポジトリを公開へ変更しない。

1. 公開予定ファイルをローカルで選別する。本キットの文書・独自図・harness.py・tests/・架空データだけのexamples/・.gitignoreを候補にし、private/、個人用設定、実レポートは含めない。ゲーム側の.gitや履歴を流用しない。
2. メール、個人パス、キー、契約情報、ログの機密情報、未許諾素材がないか、履歴を含めて確認する。ゲームの非公開データを公開しない。
3. 独自文書・図・コード・テスト・架空サンプルは承認済みのCC BY 4.0とし、LICENSE.mdを確認する。第三者のコード・画像・素材は対象外。
4. GitHubの所有者、リポジトリ名、Public、書き込み権限を確認する。既存ファイルがある場合は差分を確認する。READMEに実装範囲と未検証の制作・実機工程を明記する。
5. チェック済みの文書だけをアップロードする。公開後にログアウト状態でもREADMEと各文書が読めることを確認する。
6. 実装を加える際は小さなPRごとに検証。実行可能なスクリプトやSKILL.mdを同梱する段階で、依存・安全性・ライセンスの検査を行う。

## NOTE

1. KOUSHIROU WORKSのアカウントでログインし、アカウントを確認する。
2. NOTE_ARTICLE.mdを本文として使用する。Markdownの自動変換を前提にせず見出しとリンクをプレビューで確認する。
3. GitHubが公開できたら実際のURLを末尾へ追加する。未公開ならURLを作らない。
4. 初回記事には「調査・設計メモ」「実装と実機検証はこれから」を残す。
5. 引用した記事のスクリーンショットや作品画像を無断転載しない。画像が必要なら自作図や実際の自分の成果物を用意する。
6. 投稿後の公開URLとリンク動作を確認する。

## 更新するたびに残すもの

日付、変更点、使用ツール版、検証環境、成功・失敗・未実施、証拠、費用の測り方。調査メモと検証結果を混ぜない。
